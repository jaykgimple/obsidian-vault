# Story Engine Fixes — 2026-11-27 (daily self-healing pass)

## Defect class fixed (root cause): object-status same-frame "multiple values" false positives

The fact-checker emits free-form descriptive phrases for an object's `status`
that the enum cannot represent. In the Eldoria rebuild (series 1) magical
objects were reported as e.g. 'active, bleeding Void-energy' vs 'active,
pulsing', or 'stolen' vs 'swollen, empowered'. `_normalize_entity_value` only
keyword-maps a fixed object-status vocabulary and leaves every other phrase
unchanged, so two phrasings of the SAME state read as DISTINCT values and
`_cross_delta_contradictions` hard-failed them as "multiple values in the same
frame". The segment looped on a false positive and was parked status='error'.

Root cause: the object `status` enum is treated as strict, but the LLM emits
near-free-form descriptions the enum cannot hold. The deterministic checker is
a recall booster, not a precision authority, so non-canonical phrases must route
soft to the judge, never hard.

Fix (`core/world_state.py` `_cross_delta_contradictions`):
- A same-frame multi-value is now HARD only when EVERY distinct normalized value
  is a canonical enum member (e.g. 'stolen' vs 'driven_by_owner').
- If ANY value is non-canonical, the multi-value routes SOFT to the judge,
  mirroring free-text holder/location. A genuine enum contradiction is
  unaffected and stays hard.

Regression safety: keeps canonical 'stolen' vs 'driven_by_owner' hard; routes
'stolen' + 'swollen, empowered' and 'active, bleeding' + 'active, pulsing' soft.
Test added: `tests/test_world_state.py`
`test_same_frame_noncanonical_object_status_routes_soft` (74 tests now).
